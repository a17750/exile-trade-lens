# 功能说明

## 产品定位

“流亡译镜”只针对 `pathofexile.com/trade2`，目标是在不替用户执行交易操作的前提下，提供中文显示、中文搜索、词库更新和漏译自检。

## 已实现功能

### 1. 交易站汉化

- 物品名称和基础类型翻译。
- 交易词缀和词缀组选项翻译。
- 通货、静态项目和筛选器翻译。
- 搜索结果中的物品名、属性、需求和词缀翻译。
- 搜索结果卡片底部的 `Base Percentile`、`Armour`、`Evasion`、`Energy Shield`、`Ward` 摘要标签按白名单翻译，并保留原始数值。
- 物品卡的 `/fetch` 属性与需求由独立属性模块翻译；网页计算的 DPS、防御摘要按稳定 `data-field` 渲染，不依赖文本正则。
- 页面少量固定 UI 文本翻译。
- 物品名称、分组名称和输入框提示文字提供 DOM 精确匹配兜底。
- 构建时按稳定 ID 合并官方英文接口与中文数据，生成动态下拉菜单对照表；覆盖物品分类、筛选器、属性和选项。
- 对上游中文数据中仍保留英文的终局筛选项提供内置校正表。
- 人工校正同时记录稳定 ID 与预期英文；官方英文语义再次变化时构建会失败并要求复核，避免把旧译文静默套到新字段。
- 通过翻译交易站返回的词缀数据，使交易站原有搜索框能够匹配中文。

接口词库通过页面中的不可执行 JSON 配置节点传递，避免浏览器扩展隔离环境导致
页面拦截器拿不到词库；同时锁定已安装的 Fetch/XHR 拦截器，减少页面脚本覆盖风险。

### 2. 显示模式

- 中英双语：`增加 #% 火焰傷害 (#% increased Fire Damage)`。
- 仅繁体中文：页面只显示中文；鼠标或键盘聚焦时通过全局单例 Tooltip 显示该次翻译对应的英文原文。
- 悬停原文直接取自翻译时仍在手中的英文值，不从中文反推；同一中文对应多个英文时停用该项提示。Tooltip 使用事件委托，不为每个文本重复创建实例。
- Popup 中可启用或关闭汉化；改变设置后交易站页面自动刷新。

### 3. 词库构建

- `scripts/build-data.mjs` 不读取历史 `trade.js` 或迁移词库；运行数据只由官方 Trade API、同版本 GGPK、项目验证数据、UI 和人工覆盖生成。
- 固定网页 UI 只维护在 `data/ui.zh-TW.json`，由构建脚本写入扩展词库的 `ui` 区域，不参与物品、词缀和属性的稳定 ID 对照。
- 物品卡稳定字段从双端 Trade API 的 `equipment_filters` 自动登记；`/fetch` 属性统一通过 `itemPropertyIndex` 解析，合并 Trade API 稳定标签、带语义标记的 GGPK ClientStrings 和一致官方佐证。`data/item-fields.zh-TW.json` 只保存无法自动取得的审核例外与别名。
- 本地只读 GGPK 提取结果统一维护在 `data/ggpk.json`，并在文件内部按基础物品、名称组件、装备前后缀、被动节点、stat description、客户端字符串和来源清单分域，便于识别官方游戏文件来源。
- 被动节点只按完整 `PassiveSkills.Id + Name` 英繁配对生成 `Allocates`；CSD stat description 只有英繁模板唯一且占位符一致时才进入运行数据。游戏内容译文以同版本 GGPK 为第一梯队，台服 Trade API 只校验或补充 GGPK 未覆盖项。
- 国际服与台服官方 Trade API 在稳定 ID 对齐并通过质量门禁后写入 `data/trade-api.json`；接口失败时保留并使用最近一次有效快照，不以失败响应覆盖缓存。
- 自动读取台服官方交易数据；`stats`、`static`、`filters` 按稳定 ID 和选项 ID 合并，但不得覆盖可由同版本 GGPK 稳定键确认的译文。人工覆盖仅用于带来源与英文断言的例外，不高于无冲突 GGPK 官方配对。
- 台服物品没有稳定 ID 时不按数组位置猜测，仅在存在相同非语言稳定键时自动采用。
- 可靠来源未命中时保留完整英文并进入审核队列；不自动拆词、组合或生成翻译候选。
- 生成官方英文差异、覆盖率、质量门禁和人工审核队列。
- 提供审核命令，将确认结果连同当前官方英文写入人工覆盖文件。
- 生成压缩 JSON 数据集及 SHA-256 清单。
- 维护者可按 `Item Category` 全分类采集每类首批 10 件脱敏 `/fetch` 语料，构建期验证物品、
  属性、自带技能和词缀的整体覆盖；采样语料不参与运行时翻译，也不会将独立英台市场样本自动配对成译文。
- 请求拦截器是扩展独立维护的本地代码，不由数据构建器生成，也不下载远程 JavaScript。

### 4. 远程词库更新

- 支持 GitHub Raw 和 jsDelivr 的 HTTPS 更新清单。
- 默认清单固定为 `a17750/exile-trade-lens` 的公开 GitHub Raw 地址。
- 每 12 小时检查一次，也可在 Popup 手工检查。
- 下载后验证 SHA-256 和数据 schema。
- 更新失败时继续使用旧词库。
- 内置词库、远程词库和本地修正按优先级合并。

### 5. 漏译自检

数据来源边界：

- 目录数据来自官方国际服 `https://www.pathofexile.com/api/trade2/data/{stats,items,static,filters}`，构建时同时读取官方台服对应接口 `https://pathofexile.tw/api/trade2/data/{stats,items,static,filters}`。
- 搜索结果中的物品、词缀和属性来自官方交易站返回的 `/api/trade2/fetch/{resultIds}` 详情接口；它不是独立词库，也不能脱离当前物品和稳定 ID 进行猜译。
- 筛选面板、按钮、下拉选项和输入提示属于交易网页自身的 DOM/UI 文本，通常不来自上述 API，由项目的 UI 白名单和精确词库处理。

检测范围：

- `/api/trade2/data/stats` 中的标准词缀 ID。
- `/api/trade2/data/items` 中的标准物品名称。
- `/api/trade2/data/static` 中的静态项目 ID。
- `/api/trade2/data/filters` 中的筛选器 ID。
- `/api/trade2/fetch` 搜索结果中的标准物品、词缀和属性。
- 筛选面板、按钮、下拉选项和输入提示中仍然残留的短英文 UI 文本。

不会记录：

- POE 账号和卖家名称。
- 私聊内容和交易 whisper token。
- Cookie、POESESSID 或登录信息。
- 搜索历史和价格。
- 随机稀有物品名称。
- 用户在搜索框中输入的内容、搜索结果价格和页面链接。

漏译采集统一经过 `extension/shared/missing-report-policy.js`。输入框本身、可编辑 combobox、
`aria-controls`/`aria-owns` 关联的自动完成列表，以及输入事件后生成的动态下拉内容不会进入记录。
策略只短暂保存输入控件引用和事件时间，不读取或持久化输入值。静态 DOM 文本还必须保持稳定
1.2 秒，并在后台再次通过来源白名单。

每次安装、升级或在开发者模式重新加载扩展时，后台会开启新的代码验证批次并清空旧漏译记录。
同一版本的浏览器重启不会清空，人工修正和用户设置也不会受到影响。

漏译记录只包含类型、稳定键/ID、英文标准文本、粗粒度区域（例如 `filter-panel`）、出现次数、数据版本和首次/最近发现时间。界面扫描限定在筛选控件、按钮和下拉菜单，并排除结果、卖家和页脚区域。已经符合“中文（English）”格式的已知双语文本会被识别为已翻译，不会再次上报。记录在提交后台前会去重、截断和类型校验，本地最多保存 2,000 条。

### 6. 漏译通知与管理

- 扩展图标角标显示未忽略的漏译数量。
- Popup 显示待处理数量和本地修正数量。
- 漏译管理页支持搜索、分类过滤和显示已忽略项目。
- 支持忽略、取消忽略、删除和清空记录。
- 支持导出经过数据最小化的 JSON 报告。
- 当前没有系统通知，不申请 `notifications` 权限。
- 扩展更新后若旧管理页上下文失效，会显示重新连接提示；直接打开静态 HTML 时会提示从扩展入口进入。

### 7. 本地修正

- 可直接在漏译管理页输入译文。
- 保存前验证 `#` 数值占位符数量。
- 修正保存在 `chrome.storage.local` 的 `localOverrides`。
- 本地修正优先于远程和内置词库。
- 保存修正后，打开的交易站页面自动刷新并应用。
- 本地修正不会修改扩展安装包。

### 8. 自动消解

远程词库更新后，会重新检查待处理漏译；新词库已经包含的项目自动移除，并在更新状态中显示解决数量。

### 9. 页面运行诊断

- 标记扩展桥接是否就绪。
- 标记页面接口拦截器是否就绪。
- 标记当前词库版本。
- 记录最近成功处理的 `stats`、`items`、`static`、`filters` 或 `fetch` 接口类型。
- 诊断标记不包含账号、搜索条件、物品价格或私聊信息。

## 数据优先级

翻译来源优先级以 [翻译来源优先级](SOURCE-PRIORITY.md) 为准：同版本 GGPK 第一，台服 Trade 第二，审核项第三。下面仅描述扩展安装后的数据包覆盖顺序，不代表译文证据等级；远程和本地数据仍必须先通过来源门禁，不能用低梯队译文覆盖 GGPK：

```text
本地人工修正
  > 远程词库
  > 扩展内置词库
  > 英文原文
```

## 尚未实现

- 简体中文和 POE 专用简繁术语表。
- Chrome 商店或 GitHub Release 的安装包自动发布。
- 漏译报告匿名上传；当前只能本地查看和导出。
- 自动生成候选译文；当前需要可信数据源或人工填写。
- 本地修正的编辑、删除和导入。
- 将页面运行诊断汇总到 Popup 的健康度告警。
- Chrome 商店图标、截图、隐私政策托管页面和发布流程。
- 真实交易站版本的端到端浏览器自动化测试。

## 明确不做

- 浏览器扩展在用户侧自动批量搜索或爬取市场；维护者离线回归只做限速、首屏、脱敏分类采样。
- 自动点击私聊、自动发送消息或自动交易。
- 读取或上传会话 Cookie。
- 远程下载并执行 JavaScript。
- 修改游戏客户端文件。
