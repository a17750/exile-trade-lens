# 历史词库移除记录

`data/translations.zh-TW.json` 曾是早期迁移形成的兼容词库，现已从项目构建和运行数据中完整移除。本文件只保留历史决策记录。

## 来源与信任边界

该文件在 2026-08-27 从用户提供的历史参考脚本 `trade.js` 一次性迁移：

- 参考脚本版本：`4.27`
- 文件级 SHA-256：`588984b2562b489ca28b934fb3177ba1fd25a36eabdb928bc38df9880182d1e6`
- `provenance.kind`：`one-time-legacy-migration`

它只有文件级来源指纹，不是官方数据，也没有逐条翻译证据。原始 `trade.js` 不参与项目构建或运行；新增翻译不得继续写入这个兼容文件。

## 为什么最终移除

旧构建器曾先把历史数据复制为缺省兼容值，再由高优先级来源覆盖：

1. `stats`、`static`、`filters` 随后由国际服/台服 Trade API 按稳定 ID 覆盖。
2. 基础物品、固定名称和装备前后缀在独立领域使用同版本 GGPK 数据，运行时优先于旧 `items`/`exact` 回退。
3. `verified-labels` 和 `ui` 覆盖各自领域的历史兼容文本。
4. 带 `expectedEnglish` 的 `manual-overrides` 最后处理真正需要人工纠正的例外。

这套“先铺旧数据再覆盖”的结构容易让历史词库意外参与匹配，也无法为每条译文提供证据。项目现改为从空数据集开始，只合并官方 Trade API、同版本 GGPK、项目验证数据、UI 和人工覆盖；缺失项保留英文并上报。若未来重新评估覆盖率，也不得未经逐条验证直接恢复整份旧词库。

第一阶段曾由现已删除的 `scripts/prune-legacy-translations.mjs` 执行，只删除被高优先级数据完整且等值覆盖的记录；当时的不同译文进入审查报告。随后项目决定不再采用历史兜底，因此源文件、脚本和活动报告均已移除。

2026-08-29 的首次执行结果：

- 删除 2,872 条由 GGPK 等值覆盖的物品记录。
- 删除 4,305 条由官方 Trade API 等值覆盖的 stat 记录；其旧 `type` 字段可由 stable ID 前缀精确推导，运行时未使用。
- 删除 417 条 static、42 条 filter、17 个分组记录。
- 删除 1 条等值属性和 9 条已由 UI/人工覆盖接管的 exact 记录。
- 合计删除 7,663 条历史记录，保留 1,374 条不同译文供审查。

去重前后的有效物品解析、stat 译文、static、filter、properties、allocates 和 UI 完全一致。`exact` 减少的 367 个键全部仍由 `baseItems` 或 `fixedNames` 领域词典覆盖。扩展词库由 2,080,254 字节降至 1,857,006 字节。

上述统计仅作为历史记录，不再代表当前运行词库内容。
