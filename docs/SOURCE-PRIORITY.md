# 翻译来源优先级

本文件是项目的来源优先级硬约束。若其他文档、代码注释或实现与本文件冲突，以本文件为准，并将冲突视为待修复项。

## 总原则

游戏内容的正式译文应优先来自与当前游戏版本一致的本地 `Content.ggpk`。GGPK 是客户端实际使用的数据，能够同时提供版本指纹、稳定内部键及官方英文/繁中资源，因此属于第一梯队权威来源。

台服官方 Trade API 属于第二梯队可信来源。它主要用于：

- 验证 GGPK 提取结果是否与交易站实际展示一致；
- 在 GGPK 尚未解析到对应表、对应字段不存在或结构暂未支持时补缺；
- 提供 Trade 专属 stable ID、筛选器 ID、选项 ID 和 `/fetch` 字段结构，作为运行时定位键，而不是默认覆盖 GGPK 译文。

来源优先级为：

```text
同版本 GGPK 的稳定键英繁配对
  > 台服官方 Trade API 的相同稳定键或语义 ID
  > 带来源、expectedEnglish 和适用领域的项目审核项
  > 保留英文并上报
```

不得因覆盖率较低而把低梯队结果覆盖到已有的高梯队译文。两项官方来源冲突时必须保留高梯队结果并生成冲突报告，不得静默选择。

## 领域边界

- 基础物品、固定名称、随机名称组件、装备前后缀、技能名称、技能标签、属性名称、数值模板和 stat description：必须先寻找 GGPK 稳定来源。
- Trade stat/filter/static ID：继续作为官网请求与页面字段的稳定身份；译文仍应先尝试连接到 GGPK，连接失败后才使用台服 Trade 对照。
- 交易站独有 UI、卖家状态、按钮及官网交互文案：若 GGPK 没有对应资源，允许使用 Trade API 或项目 UI 词库；不得反向进入游戏内容领域。
- 社区词库、历史 `trade.js`、机器翻译和英文分词推测不属于正式来源梯队，只能供人工调查。

## 技能宝石当前状态

技能宝石标签由 GGPK `GemTags` 的英文/繁中表按稳定语义 ID 配对，位于
`data/ggpk.json#/skillGemTags`，属于第一梯队。`data/skill-tags.zh-TW.json` 保存台服 `/fetch` 的直接
语义 ID 对照，属于第二梯队：同 ID 只做一致性校验，GGPK 缺项时才补位，冲突时不得覆盖 GGPK。
属性标签和资源模板继续由 GGPK `ClientStrings` 提供，CSD 链接词仅为末级精确后备。

## 构建与审计要求

- 每条正式译文应记录来源层级、稳定键和源版本指纹。
- 构建器必须阻止第二梯队覆盖第一梯队。
- 来源冲突、结构漂移、占位符变化和一对多译文必须进入报告。
- 自动更新 GGPK 后应重新生成规范化数据并运行完整回归；Trade 更新只能补充尚未被 GGPK覆盖的稳定记录。

按 Trade Item Category 扩充 GGPK 数据域的具体顺序与当前缺口见
[GGPK 分类覆盖与提取路线图](GGPK-CATEGORY-COVERAGE.md)。
